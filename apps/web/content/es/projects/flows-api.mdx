## Contexto

Algunos productos necesitan más que una sola llamada de generación: un
usuario puede querer hacer upscale de una imagen y luego generar un vídeo
a partir de ella, o encadenar varios modelos como una sola acción
lógica. Hacerlo en el cliente significa que cada integrador reimplementa
la misma lógica de encadenado, y paga los round-trips entre pasos.

## Qué construí

Flows API es el componente de la plataforma que permite combinar varios
modelos de IA en una sola llamada de API: un flow describe una secuencia
de pasos (p. ej. generar → upscale → convertir a vídeo), y la plataforma
lo ejecuta como una sola tarea, devolviendo progreso y resultado final a
través del mismo mecanismo de webhooks que usa el resto de la plataforma.

## Arquitectura

Flows API está construida sobre la misma base que el resto de la
plataforma:

- **Especificación** — las definiciones de flow y sus entradas/salidas
  se describen en el mismo contrato OpenAPI que los endpoints de un solo
  modelo, así que la generación de clientes y la validación funcionan
  igual.
- **Servidor** — el servidor FastAPI resuelve los pasos de un flow,
  llama a los servicios de modelo correspondientes en orden, y trata el
  flow como una sola tarea.
- **Gateway y facturación** — el uso se mide por paso, así que el coste
  refleja los modelos realmente invocados, no un precio plano por flow.

Al reutilizar el mismo pipeline spec → servidor → gateway → docs, añadir
un nuevo tipo de paso a un flow sigue el mismo proceso que dar de alta
cualquier otro modelo.

## Resultado

Una capa de orquestación para flows de generación multi-paso, viva como
parte de la [plataforma de API en producción](https://www.freepik.com/api),
con documentación de referencia en [docs.freepik.com](https://docs.freepik.com).
