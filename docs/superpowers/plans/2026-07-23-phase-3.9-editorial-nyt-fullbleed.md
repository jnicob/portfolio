# F3.9 — Skin Editorial «NYT» + puntero full-bleed · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** El skin Editorial adopta identidad de periódico NYT (paleta B/N + azul, disposición propia en home/CV/detalle vía CSS-only) y el canvas del puntero de la home pasa a full-bleed manteniendo el contenido en `max-w-5xl`.

**Architecture:** Los tokens del skin se reemplazan en `globals.css` (el test de contraste AA existente los cubre automáticamente). La disposición vive en un parcial nuevo `apps/web/src/app/skins/editorial.css` — cada regla escopada a `[data-skin='editorial']`, colores solo vía `var(--token)`, DOM intacto (solo se añaden atributos `data-*` inertes como hooks). `HomeBackground` se parte en capa full-bleed (canvas) + capa `max-w-5xl` (contenido).

**Tech Stack:** Next.js 16 App Router (static export default), Tailwind v4 con `@theme inline`, Vitest + Testing Library, CSS puro para el skin.

**Spec:** [docs/superpowers/specs/2026-07-23-phase-3.9-editorial-nyt-fullbleed-design.md](../specs/2026-07-23-phase-3.9-editorial-nyt-fullbleed-design.md)

## Global Constraints

- Colores SOLO vía tokens semánticos (`var(--…)`); cero hex fuera de los bloques de definición de tokens en `globals.css`.
- Cero JS nuevo, cero client components nuevos, cero cambios de orden en el DOM (First Load JS no puede crecer).
- TypeScript strict; lint, format, typecheck y los 652 tests actuales deben seguir verdes en cada commit.
- Los otros 3 skins (dev-tool, terminal, vibrant) no cambian de comportamiento.
- Commits pequeños `tipo: descripción`; cada task termina en verde.
- Los comandos se ejecutan desde la raíz del monorepo salvo indicación contraria.

```ts
import { readdirSync, readFileSync } from 'node:fs';
import path from 'node:path';
import { describe, expect, it } from 'vitest';

/*
 * Invariantes del parcial de disposición del skin editorial (spec F3.9 §2):
 * - todo selector escopado a [data-skin='editorial'] (no puede filtrar a otros skins);
 * - cero colores hex (hard rule: colores solo vía tokens);
 * - todo hook data-* que use existe en el código (sin selectores muertos).
 */

const CSS_PATH = path.resolve(__dirname, 'editorial.css');
const css = readFileSync(CSS_PATH, 'utf-8');

/** Selectores de regla: lo que precede a cada `{`, ignorando comentarios y @media. */
function ruleSelectors(source: string): string[] {
  const clean = source.replace(/\/\*[\s\S]*?\*\//g, '').replace(/@media[^{]*\{/g, '');
  const selectors: string[] = [];
  for (const match of clean.matchAll(/(^|\})\s*([^@{}]+)\{/g)) {
    selectors.push(...(match[2] ?? '').split(',').map((s) => s.trim()));
  }
  return selectors.filter(Boolean);
}

function sourceFiles(dir: string): string[] {
  return readdirSync(dir, { recursive: true, withFileTypes: true })
    .filter((entry) => entry.isFile() && /\.(tsx?|css)$/.test(entry.name))
    .map((entry) => path.join(entry.parentPath, entry.name));
}

describe('editorial.css (disposición del skin editorial)', () => {
  it('todo selector está escopado a [data-skin=editorial]', () => {
    const selectors = ruleSelectors(css);
    expect(selectors.length).toBeGreaterThan(0);
    for (const selector of selectors) {
      expect(selector, selector).toMatch(/^\[data-skin='editorial'\]/);
    }
  });

  it('no contiene colores hex (solo tokens)', () => {
    expect(css).not.toMatch(/#[0-9a-fA-F]{3,8}\b/);
  });

  it('cada hook data-* que usa existe en el código de la app', () => {
    const hooks = [...new Set(css.match(/data-(?!skin|theme)[\w-]+/g) ?? [])];
    expect(hooks.length).toBeGreaterThan(0);
    const appSource = sourceFiles(path.resolve(__dirname, '..', '..'))
      .filter((file) => !file.endsWith('editorial.css') && !file.endsWith('editorial-css.test.ts'))
      .map((file) => readFileSync(file, 'utf-8'))
      .join('\n');
    for (const hook of hooks) {
      expect(appSource, `hook ${hook} sin uso en la app`).toContain(hook);
    }
  });
});
```
