## Bloque A — media-kit 0.5

### A1. Fix: "seguir el mouse" no funciona en fullscreen

Diagnóstico (exploración, `media-lightbox.tsx` + `use-zoom-pan.ts`):

- **Causa 1 (foco):** el flujo real es click en el botón ⤢ → el foco queda en ese botón → `onKeyDown` ignora Espacio cuando `target.closest('button, a')` (`media-lightbox.tsx:354`) → el space-pan (mouse-follow) nunca se activa. No es exclusivo de fullscreen, pero es donde siempre se manifiesta.
- **Causa 2 (bounds):** `bounds()` (`use-zoom-pan.ts:48-59`) se lee en vivo, pero el estado `{tx,ty}` NO se re-clampa al cambiar el tamaño del viewport (fullscreenchange/resize); además `canPan` puede quedar obsoleto y el pan "no mueve nada".

**Decisiones:**

1. Tras `toggle()` de fullscreen desde el botón de la toolbar, el foco se devuelve al **root del dialog** (`dialogRef.current.focus()`), tanto al entrar como al salir. El root ya tiene `tabIndex={-1}` (verificar; añadirlo si no). Así Espacio vuelve a activar el follow inmediatamente.
2. `use-zoom-pan` escucha `resize` de window y `fullscreenchange` de document mientras está montado y **re-clampa** el estado actual (`setState(clampState(state))`) forzando también el recálculo de `canPan`.
3. Tests nuevos (hueco detectado: no existe ningún test fullscreen+pan): (a) tras toggle fullscreen el foco está en el root y Espacio+move panea; (b) un resize dispara re-clamp (estado fuera de límites vuelve a límites).

### A2. Tooltips con delay en todos los controles

Hoy: tooltip CSS sin delay, acotado a `.mk-lightbox__corner` (`styles.css:360-390`); la toolbar solo tiene `aria-label`.

**Decisiones:**

1. Se generaliza la infraestructura: el selector pasa de `.mk-lightbox__corner button[data-mk-tooltip]` a `.mk-lightbox [data-mk-tooltip]`, con posicionamiento por zona: en la toolbar (abajo) el tooltip aparece **encima** del botón; en la esquina (arriba-dcha) **debajo**, como hoy. Zona vía atributo `data-mk-tooltip-pos="above" | "below"` (default `below`).
2. **Delay:** aparición con `transition: opacity 120ms ease-out; transition-delay: 600ms` en hover; sin delay al desaparecer (`transition-delay: 0ms`) ni en `:focus-visible` (el teclado no espera).
3. Todos los botones de `LightboxControls` (zoom −/+, reset, fit, fullscreen) y el botón close reciben `data-mk-tooltip` con el mismo texto que su `aria-label` (reutiliza `MediaLightboxLabels`, cero claves nuevas).
4. `prefers-reduced-motion`: el tooltip aparece/desaparece sin transición (delay se mantiene — es tiempo, no movimiento).

### A3. CompareSlider: modos nuevos (`compareMode`)

Prop nueva **opcional** `compareMode?: 'wipe' | 'onion' | 'blink' | 'side-by-side'` (default `'wipe'` = comportamiento actual, cero breaking). El eje actual (`clip-path` + `--mk-compare-pos`) solo aplica a `wipe`.

| Modo           | Render                                                                                             | Rol del slider/handle                                                                          | Notas                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `wipe`         | actual (clip-path)                                                                                 | posición del divisor 0-100                                                                     | sin cambios                                                                                                             |
| `onion`        | `after` superpuesto con `opacity: pos/100`; sin divisor visual                                     | opacidad 0-100 (`aria-valuetext: "{pos}% after"`)                                              | mismo handle/teclado                                                                                                    |
| `blink`        | alterna before/after con timer (800 ms); sin divisor ni handle                                     | no hay slider; botón `role="switch"` play/pausa (reutiliza pauseLabel/resumeLabel + aria-live) | timer con `setInterval`, limpio al desmontar; `prefers-reduced-motion` → arranca **pausado**                            |
| `side-by-side` | grid 2 columnas (o 2 filas si `orientation="vertical"`), ambos lados completos con `overlayLabels` | no hay slider ni handle                                                                        | dentro del lightbox hereda el zoom/pan del visor → **zoom sincronizado gratis** (el transform envuelve todo el compare) |

- `MediaLightbox.compare` gana passthrough opcional `compareMode` (mismo tipo).
- CSS: variantes por `data-compare-mode` en el root `.mk-compare`.
- Tests por modo: render, teclado/estado, cleanup del timer de blink, reduced-motion arranca pausado.

### A4. `SpotlightReveal` (componente nuevo)

Lupa/linterna que revela el medio `reveal` sobre el `base` bajo el puntero. El complemento de más impacto del CompareSlider.

**API** (`src/spotlight-reveal/spotlight-reveal.tsx`):

```ts
type SpotlightRevealProps = {
  base: ReactNode | MediaSource; // capa siempre visible
  reveal: ReactNode | MediaSource; // capa revelada bajo la lente
  label: string; // nombre accesible del área interactiva
  radius?: number; // px de la lente, default 110
  defaultPosition?: { x: number; y: number }; // % 0-100, default {50,50}
  className?: string;
  overlayLabels?: { base?: string; reveal?: string }; // badges aria-hidden
};
```

**Comportamiento:**

- La capa `reveal` está superpuesta (`position:absolute; inset:0`) y recortada con `clip-path: circle(var(--mk-spot-r) at var(--mk-spot-x) var(--mk-spot-y))`.
- Puntero: la lente sigue `pointermove` (coordenadas relativas al contenedor, mismas mates que `positionFromPointer` del slider). Al salir del área la lente se oculta suavemente (`--mk-spot-r → 0`).
- Teclado: contenedor `tabIndex={0}` con `role="slider"` 2D descartado; se usa `aria-roledescription="spotlight"` + flechas mueven la lente en pasos de 5% (Shift = 1%), `Home` centra, `Escape` oculta la lente. Con foco, la lente está siempre visible en su última posición.
- `prefers-reduced-motion`: sin transición del radio (aparición instantánea); el seguimiento del puntero no es animación (es posición directa), se mantiene.
- Lados `MediaSource` → `<img draggable={false}>` como en CompareSlider (misma utilidad compartida si es razonable extraerla; no duplicar lógica de carga).
- CSS: bloque `.mk-spotlight` nuevo en `styles.css`; variables públicas nuevas `--mk-spot-ring` (borde de la lente) documentadas en README.

### A5. `FilterGallery` (componente nuevo)

Grid con filtrado/reordenado animado (FLIP manual, sin dependencias, sin View Transitions API — compat y SSR-safe).

**API** (`src/filter-gallery/filter-gallery.tsx`):

```ts
type FilterGalleryItem = { id: string; categories: readonly string[]; node: ReactNode };
type FilterGalleryProps = {
  items: readonly FilterGalleryItem[];
  filter?: string | null; // controlado; null = todos
  defaultFilter?: string | null; // no controlado
  onFilterChange?: (f: string | null) => void;
  categories?: readonly { id: string; label: string }[]; // si se pasa, renderiza la botonera
  allLabel?: string; // default 'All'
  label: string; // aria-label del grupo de filtros y del grid
  className?: string;
  duration?: number; // ms de la animación FLIP, default 240
};
```

**Comportamiento:**

- Filtrar = los items cuya `categories` no incluye el filtro se ocultan; los visibles se recolocan con **FLIP**: medir rects antes (First), aplicar cambio de layout (Last), `transform` inverso (Invert), animar a identidad con WAAPI `element.animate` (Play). Items que entran: fade+scale desde 0.96; items que salen: retirada inmediata en v1 (la animación de salida exigiría render diferido — YAGNI, documentado como extensión).
- `prefers-reduced-motion` (media query en JS): sin animación, cambio instantáneo.
- Botonera (si `categories`): `role="group"` de botones toggle con `aria-pressed`; el activo con estilo `--mk-*`; SIEMPRE incluye "All".
- SSR-safe: primer render sin medir; las medidas solo en efectos.
- Tests: filtrado controlado/no controlado, aria-pressed, items ocultos fuera del DOM accesible, reduced-motion sin `animate` (spy).

### A6. `VideoScrubPreview` (componente nuevo)

Hover-scrub de vídeo (patrón miniaturas de YouTube).

**API** (`src/video-scrub-preview/video-scrub-preview.tsx`):

```ts
type VideoScrubPreviewProps = {
  src: string;
  poster?: string;
  label: string; // aria-label
  className?: string;
  scrubOnFocus?: boolean; // teclado: flechas ±5% (default true)
};
```

**Comportamiento:**

- `<video muted playsInline preload="metadata" poster>`; al mover el puntero sobre el área, `currentTime = (x / width) * duration` (throttle con rAF); al salir, vuelve al poster (pausa + `currentTime = 0`).
- Barra de progreso fina inferior (`--mk-compare-pos`-style var `--mk-scrub-pos`).
- Teclado: `tabIndex={0}`, flechas ±5% de `duration`, Home/End.
- `duration` puede no estar disponible hasta `loadedmetadata`: gate interno; sin metadata el scrub no hace nada (sin errores).
- Sin autoplay, sin sonido; `prefers-reduced-motion` no aplica (el scrub es interacción directa del usuario).

## Bloque B — Showcase UX v2

### B1. El índice filtra de verdad

- `ShowcaseIndex.onSelect` deja de hacer `window.location.hash = id` (scroll). La página gana estado de filtro (client component contenedor `ShowcaseSections`): seleccionar una sección en el índice **muestra solo esa sección**; una entrada "Todas" (primera de la lista, i18n) restaura todo.
- El filtro se refleja en la URL (`#section-id`) para deep-linking, pero la navegación es por filtrado, no por scroll.
- Transición de secciones: fade suave (150 ms, reduced-motion → sin transición). No se usa FilterGallery aquí (las secciones son bloques pesados; FLIP innecesario) — FilterGallery tiene su propia demo en B4.
- Al filtrar, foco/anuncio: `aria-live="polite"` con "Mostrando: {sección}" (clave i18n nueva).

### B2. Tabs sin desplazamiento real

- `TabPanel` pasa de `hidden` (display:none, altura 0) a **paneles apilados en la misma celda de grid**: contenedor de paneles `display:grid`, cada panel `grid-area: 1/1`; el inactivo `visibility: hidden` + `aria-hidden` (mantiene caja → la altura del contenedor = la del panel más alto → **cero salto**). El panel inactivo ya no es focusable (visibility lo garantiza).
- Aparición del panel activo con fade 150 ms (reduced-motion → corte).
- El test de 2.6 que aseguraba "montado pero hidden" se actualiza al contrato nuevo (montado, `visibility:hidden`): cambio de contrato documentado, no regresión.

### B3. Radii y estados coherentes

- El `<pre>` del panel api pasa de `rounded-card` a `rounded-control` (bloque de código = control, coherente con tabs vecinas).
- `.prose-portfolio code`: `border-radius: 0.25rem` hardcodeado → `calc(var(--radius-control) / 2)` (sigue las skins).
- `Input` y `Select` ganan `transition-colors` + `hover:border-fg-muted` (paridad con Button).
- Revisión rápida de la sección media-kit: demos en cards con `rounded-card` consistente.

### B4. Demos nuevas en el showcase (media-kit 0.5 + colorización real)

- **Colorización real para los 2 primeros ejemplos:** se sustituyen `photo-before.svg`/`photo-after.svg` por **una única foto real** (`/demo/landscape.webp`, ≤ 200 kB, ~1600 px, `width`/`height` explícitos) generada con IA por el orquestador (Magnific MCP) — el "antes" se deriva con `filter: saturate(0.12) contrast(0.92) brightness(0.96)` (patrón del retrato, una sola descarga). Los ejemplos drag y hover comparten imagen.
- **Demo `compareMode`:** un CompareSlider con botonera para alternar wipe/onion/blink/side-by-side (misma imagen paisaje).
- **Demo `SpotlightReveal`:** paisaje B/N como `base` y color como `reveal` (una imagen + filtro, cero assets extra).
- **Demo `FilterGallery`:** grid de 8 tiles SVG/emoji de categorías (image/video/audio) con botonera — sirve además de test visual del FLIP.
- **Demo `VideoScrubPreview`:** clip corto (`/demo/scrub.mp4`, ≤ 1.5 MB, 3-5 s, sin audio) generado con IA por el orquestador (Magnific video) o reutilizando un mock existente si el peso lo exige.
- La sección media-kit del showcase se reorganiza en sub-bloques con intro cada uno (patrón 2.6); TOC del índice gana las entradas nuevas.

## Bloque C — Componentes de impacto en la app

Los cuatro viven en `apps/web` (no en el paquete), usan tokens y tienen entrada en el showcase. Todos client components ligeros, RSC-friendly desde las páginas.

### C1. `AnimatedMetric` (`components/ui/animated-metric/`)

- Props: `{ value: string; label?: string; duration?: number }`. Parsea `value` (`"25+"`, `"1.000+"`, `"40+"`) → anima el número 0→N con `requestAnimationFrame` + easing out-cubic cuando entra en viewport (IntersectionObserver, una vez), conservando prefijo/sufijo y separador de miles del literal original.
- `prefers-reduced-motion` o sin IO (SSR/tests): muestra el valor final directo. `aria-label` = valor final (el conteo es decorativo: el nodo animado `aria-hidden`, el valor real en `sr-only`).
- Se aplica a los `<dd>` de métricas de `ProjectCard` (plataforma: 25+, 40+) — prop opt-in `animateMetrics?: boolean` en ProjectCard, activada en destacados de la home.

### C2. `TiltCard` (`components/ui/tilt-card/`)

- Wrapper `{ children, maxTilt?: number /* default 4deg */ }`: tilt 3D sutil siguiendo el puntero (`perspective(800px) rotateX/rotateY`) + glow radial que sigue el cursor (`--tilt-glow-x/y`, `background: radial-gradient(... var(--color-accent) 8%, transparent)` con opacidad baja).
- Solo con `(hover: hover) and (pointer: fine)` (media query JS) — en touch es un div normal. `prefers-reduced-motion`: sin tilt, glow estático al hover. Transform con `will-change` solo durante hover.
- Se aplica envolviendo las cards del grid de destacados de la home (ProjectCard + MoreProjectsCard quedan intactos por dentro).

### C3. `ApiRequestPlayer` (`components/showcase/api-request-player.tsx`)

- Muestra un bloque request (método+path+JSON) con botón "Run ▸": al ejecutarlo, panel response pasa por `pending` (spinner + latencia simulada 600 ms) → la respuesta JSON se "escribe" en streaming (rAF, ~800 caracteres/s) con caret; luego estado `done` con status badge `200 OK` y botón copy.
- Datos tipados en `apps/web/src/data/api-demo.ts` (request/response de ejemplo estilo Freepik API — inventado genérico, sin datos reales). Nada inline en JSX; labels por messages.
- `prefers-reduced-motion`: respuesta aparece completa sin typing. Reejecutable. Reutilizable en F4 (el playground le pasará request/response reales).
- Entrada propia en el showcase (sección nueva `api-player`).

### C4. Hero canvas reactivo (`components/home/hero-canvas.tsx`)

- `<canvas>` absolutamente posicionado detrás del contenido del Hero: grid de puntos (~24 px de paso) cuya opacidad/desplazamiento reacciona al puntero (radio ~140 px), color leído de `getComputedStyle(document.documentElement).getPropertyValue('--color-accent')` y re-leído al cambiar `data-theme`/`data-skin` (MutationObserver sobre `<html>`).
- rAF pausado cuando: `prefers-reduced-motion`, pestaña oculta (`visibilitychange`), o puntero fuera del hero (estado de reposo estático, sin bucle). `pointer-events: none`; `aria-hidden`.
- Intensidad sutil (opacidad máx ~0.35). Cero dependencia; ~120 líneas.

### C5. Integración e i18n

- Home: Hero envuelto con `HeroCanvas`; destacados con `TiltCard`; métricas de plataforma con `AnimatedMetric`.
- Showcase: secciones nuevas `api-player` y `impact` (TiltCard/AnimatedMetric demos) + TOC.
- Todas las labels nuevas en `messages/{es,en}.json` (el test de paridad ya lo vigila).
