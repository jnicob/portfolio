## 1. Bloque A — G1: bug tema+idioma (systematic-debugging)

Se trata como bug: **reproducir antes de arreglar**.

1. Reproducción con Playwright (dev server y export estático) siguiendo la secuencia exacta: alternar tema → cambiar idioma con el LocaleSwitcher → observar `data-theme`/apariencia.
2. Diagnóstico sistemático. Sospechosos iniciales (a confirmar, no a asumir): el ThemeSwitcher no persiste el tema donde `appearance-init` lo lee al navegar, o el LocaleSwitcher provoca navegación con documento nuevo y `appearance-init` re-aplica un valor obsoleto/de sistema.
3. Fix mínimo con **test de regresión** que cubra la secuencia completa (tema toggled + cambio de locale conserva el tema).
4. Si la reproducción demuestra que NO es bug (comportamiento esperado del modo «sistema»), se documenta la conclusión en el ledger y se cierra sin tocar código.

## 2. Bloque B — G2: sistema de layouts (media-kit 0.7.0 + galería)

### 2.1 Por qué JS y no CSS-only (análisis clean-room de pikaso y fc_freepik_web)

Ambos repos internos usan **JS de columnas balanceadas**; ninguno usa CSS multi-column en producto. Razones documentadas en su código que aplican aquí:

- **Orden de lectura**: CSS columns llena column-major → lector de pantalla/Tab recorren en orden no visual (violaría nuestro AA). fc_freepik_web mantiene orden DOM = orden de datos y solo mueve posición visual.
- **Alturas conocidas sin medir imágenes**: ambos derivan la altura del `width/height` del asset; nuestra `gallery.ts` ya tipa esas dimensiones.
- **Estabilidad al refiltrar**: packing determinista; con CSS columns los ítems saltarían de columna al filtrar.
- (Virtualización, la razón dominante en los repos internos, no aplica: 16 ítems.)

Regla clean-room de F3: los repos internos son referencia de patrón; **cero código ni contenido interno en este repo**.

### 2.2 media-kit 0.7.0 (aditivo, cero breaking)

1. **`FilterGalleryItem.aspectRatio?: number`** (ancho/alto). Los layouts nuevos lo requieren; sin él, fallback documentado (1:1) — el layout `grid` lo ignora.
2. **`FilterGalleryProps.layout?: 'grid' | 'masonry' | 'justified'`**, default `'grid'` (comportamiento actual intacto).
3. **Motor de posiciones puro y testeable**: `(aspectRatios, anchoContenedor, columnas|altoFila) → { x, y, width, height }[]` + altura total del contenedor.
   - **Masonry**: columnas de ancho fijo, packing «columna más corta primero», determinista.
   - **Justified**: filas de alto uniforme; anchos proporcionales al AR; la fila se ajusta para llenar el ancho exacto; última fila sin estirar.
4. **Aplicación**: `<li>` con `position: absolute` + `left/top` (NO `transform`: el FLIP anima `transform` por encima sin conflicto); el `<ul>` recibe la altura calculada. **Orden DOM = orden de datos.**
5. **Columnas responsive por ancho de contenedor** (ResizeObserver sobre el `<ul>`): 2 → 3 → 4-5 máximo; umbrales por ancho mínimo de tile (patrón container-query en JS), constantes documentadas. SSR-safe: sin medición en servidor; con `layout` distinto de `grid` el primer render cliente calcula antes de pintar (el selector solo actúa post-hidratación, el HTML prerenderizado siempre es grid).
6. **Convivencia con FLIP + salida animada**: el cambio de layout re-posiciona con la misma animación FLIP (posiciones medidas con `getBoundingClientRect`, ya agnósticas del layout); `prefers-reduced-motion` = recolocación instantánea (mecanismo existente).
7. **CHANGELOG 0.7.0** (Added: layout masonry/justified, aspectRatio) + README (props, fallbacks, constantes de columnas).

## 3. Bloque C — G3: API player con selector de endpoint

- **`api-demo.ts` pasa de 1 a 4 ejemplos** tipados: imagen · vídeo · audio · error. Cada uno: método, path, body, respuesta simulada y preview (tipo de medio o error). Estilo Freepik/Magnific API genérico, sin datos internos.
- **Selector de endpoint** en el panel request (encima del badge método+path): al cambiar se actualizan método/path/body y se resetea el visor a idle; Run produce el flujo streaming existente con el resultado del ejemplo.
- **Vídeo y audio reutilizan assets de la galería** (`gallery.ts`) — 0 bytes de media nueva; el preview de vídeo usa `<video controls>` con poster, el de audio carátula + player (mismos patrones del lightbox de la galería). Fullscreen ⛶ del visor funciona para los 3 tipos de medio.
- **Error**: respuesta 4xx simulada; tab Response muestra el JSON de error (mismo streaming), tab Preview un estado de error diseñado (patrón de estados explícitos del repo, sin medio).
- **Cero layout shift**: se mantiene la altura reservada; el test de altura estable se amplía a los 4 ejemplos (incluido el cambio de endpoint). El backlog «preview dims» (§5) entra aquí porque se rediseña esa zona.
- **Etapa posterior anotada para F4** (fuera de alcance): code viewer y parámetros personalizables.
